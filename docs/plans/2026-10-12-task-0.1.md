## Goal
Ensure ID continuity across legacy bare-numeric job records and new adapter-prefixed records (`jobsdb_<id>`) in both the Turso database and local state management (`seen_jobs.json`), preventing duplicate Telegram alerts and redundant database insertions.

---

## Changes

### 1. `state_manager.py`
- **All-Digit Rule Parity**:
  - Align Python key parsing with the SQL migration rule (`id <> '' AND id NOT GLOB '*[^0-9]*'`) using `str(k).isascii() and str(k).isdigit()`. A key is migrated to `jobsdb_<k>` if and only if it is non-empty and composed entirely of ASCII digits. Non-ASCII digit characters (e.g. Thai numerals "๑๒๓") must NOT be prefixed.
- **In `StateManager._load()` (v2 schema, around lines 59–65)**:
  - When iterating over `data.get("seen")`:
    - If `str(k).isascii() and str(k).isdigit()`, canonicalize the ID as `f"jobsdb_{k}"`. Otherwise keep `str(k)`.
    - **Collision Resolution**: If both bare numeric (`"95104887"`) and prefixed (`"jobsdb_95104887"`) keys exist in `seen`, merge them into `jobsdb_95104887` and preserve the newer ISO date (`max(date1, date2)` or non-None date).
- **In `StateManager._load()` (legacy v1 schema, around lines 69–75)**:
  - When iterating over `data.get("seen_ids")`:
    - Canonicalize `job_id` to `f"jobsdb_{job_id}"` if `str(job_id).isascii() and str(job_id).isdigit()`.
    - Retain existing today-stamped TTL logic.
- **Hermetic File Isolation**:
  - Verify all operations respect `self.state_file` passed in constructor so tests run isolated in temporary directories.

## Tests to Add

Create `tests/test_state_manager.py` (all tests use `tempfile.TemporaryDirectory()`, never touching `data/seen_jobs.json`):

1. `test_load_migrates_bare_numeric_ids_in_v2_seen`:
   - **Asserts**: A v2 state dictionary `{"version": 2, "seen": {"95104887": "2026-10-10", "jobsdb_12345": "2026-10-10", "blognone_slug": "2026-10-10", "๑๒๓": "2026-10-10"}}` is loaded into memory as `{"jobsdb_95104887": "2026-10-10", "jobsdb_12345": "2026-10-10", "blognone_slug": "2026-10-10", "๑๒๓": "2026-10-10"}` (Thai numerals "๑๒๓" are NOT prefixed).
   - **Why it fails today**: `StateManager._load()` currently returns `{str(k): v for k, v in seen.items()}`, preserving bare numeric `"95104887"`.

2. `test_load_migrates_bare_numeric_ids_in_v1_legacy`:
   - **Asserts**: A legacy v1 payload `{"seen_ids": ["95104887", "blognone_slug", "๑๒๓"]}` loads as `{"jobsdb_95104887": "<today>", "blognone_slug": "<today>", "๑๒๓": "<today>"}`.
   - **Why it fails today**: `StateManager._load()` returns `{str(job_id): today for job_id in legacy_ids}`, leaving bare `"95104887"`.

3. `test_load_collision_keeps_newer_date`:
   - **Asserts**: If a state file contains both `"95104887": "2026-10-08"` and `"jobsdb_95104887": "2026-10-11"`, or `"95104887": "2026-10-12"` and `"jobsdb_95104887": "2026-10-09"`, loading resolves to `{"jobsdb_95104887": "<later ISO date>"}`.
   - **Why it fails today**: Today, `"95104887"` is not migrated to `"jobsdb_95104887"` on load, so no collision check or date comparison occurs; both coexist as separate keys.

4. `test_save_persists_migrated_ids`:
   - **Asserts**: Initializing `StateManager` in a temporary directory with a file containing bare numeric IDs and calling `save()` writes the `jobsdb_` prefixed IDs to the JSON file on disk atomically.
   - **Why it fails today**: Saved state retains bare numeric IDs.

5. `test_filter_new_jobs_recognizes_migrated_id_as_seen`:
   - **Asserts**: Given a state file initialized in a temporary directory with bare ID `"95104887"`, passing an incoming scraper job `{"id": "jobsdb_95104887", "title": "Dev", "company": "Co", "url": "https://..."}` to `state.filter_new_jobs()` returns an empty list (i.e. recognizes it as already seen and suppresses duplicate alerts).
   - **Why it fails today**: `is_new("jobsdb_95104887")` evaluates to `True` because the stored ID is `"95104887"`.

## Production Touch Points

### Turso Database Migration (Manual SQL Execution)
Per `AGENTS.md`, AI agents must never run SQL statements that write to production Turso (`INSERT`, `UPDATE`, `DELETE`, `ALTER`, `DROP`). The user must run the following migration commands.

The exact `source` value written by `src/scrapers/jobsdb.py` (line 115) is `'jobsdb'`.

#### A. Read-only checks (record every result)
```sql
PRAGMA foreign_keys;
PRAGMA foreign_key_list(skills_extracted);
SELECT DISTINCT source FROM jobs;
SELECT count(*) FROM jobs;
SELECT count(*) FROM skills_extracted;
SELECT count(*) FROM jobs WHERE id GLOB 'jobsdb_*';                        -- must be 0
SELECT count(*) FROM skills_extracted WHERE job_id GLOB 'jobsdb_*';   -- must be 0
SELECT count(*) FROM jobs WHERE id <> '' AND id NOT GLOB '*[^0-9]*';       -- rows to migrate
SELECT count(*) FROM skills_extracted WHERE job_id <> '' AND job_id NOT GLOB '*[^0-9]*';
SELECT count(*) FROM skills_extracted s LEFT JOIN jobs j ON j.id = s.job_id WHERE j.id IS NULL;  -- orphans before
```

If either jobsdb_* count is not 0, do not run section B; stop and report the results.

#### B. Migration, one transaction
```sql
BEGIN;
PRAGMA defer_foreign_keys = ON;
UPDATE jobs SET id = 'jobsdb_' || id, source = 'jobsdb'
  WHERE id <> '' AND id NOT GLOB '*[^0-9]*';
UPDATE skills_extracted SET job_id = 'jobsdb_' || job_id
  WHERE job_id <> '' AND job_id NOT GLOB '*[^0-9]*';
COMMIT;
```

#### C. After: total counts unchanged, 0 all-digit ids in both tables, orphan count equal to before
```sql
-- 1. Total counts must be unchanged from section A:
SELECT count(*) FROM jobs;
SELECT count(*) FROM skills_extracted;

-- 2. Zero all-digit IDs remaining in both tables:
SELECT count(*) FROM jobs WHERE id <> '' AND id NOT GLOB '*[^0-9]*';                 -- must be 0
SELECT count(*) FROM skills_extracted WHERE job_id <> '' AND job_id NOT GLOB '*[^0-9]*';  -- must be 0

-- 3. jobsdb_ prefixed count:
SELECT count(*) FROM jobs WHERE id GLOB 'jobsdb_*';
SELECT count(*) FROM skills_extracted WHERE job_id GLOB 'jobsdb_*';

-- 4. Orphan count must be equal to section A:
SELECT count(*) FROM skills_extracted s LEFT JOIN jobs j ON j.id = s.job_id WHERE j.id IS NULL;
```
