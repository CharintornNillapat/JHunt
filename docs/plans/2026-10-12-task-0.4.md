# Plan: Task 0.4 — Restore Scraper Keyword Coverage & Detail Fetch Optimization

**Date:** 2026-10-12  
**Task ID:** 0.4  
**Reference:** `docs/audits/2026-10-12-remediation-plan.md` (Task 0.4), `docs/audits/2026-10-12-architecture-reflection.md` (Section 2)

---

## Goal
Restore full multi-keyword job market coverage across all scraper adapters by tracking item limits per keyword (`keyword_count >= limit`) instead of total accumulated items, configuring per-adapter limits in `main.py`, and eliminating redundant detail page HTTP fetches for already-known jobs while applying polite delays to new detail fetches.

---

## Disagreements / Alignment Notes
1. **JobsDB Per-Keyword Limit Value**:  
   `docs/audits/2026-10-12-remediation-plan.md` (line 84) lists `150 per keyword` for JobsDB, while `docs/audits/2026-10-12-architecture-reflection.md` (line 203) mentions `300 per keyword`. Following the remediation plan task specification, the default limit will be set to `150` for JobsDB and `30` for Blognone and JobThai in `main.py`.

---

## Current Behavior (Evidence)
1. **Premature Keyword Loop Termination:**  
   In `src/scrapers/jobsdb.py` (lines 145, 160, 179), `src/scrapers/blognone.py` (lines 226, 241, 260), and `src/scrapers/jobthai.py` (lines 231, 246, 265), the scraping loop checks `if len(jobs) >= limit: break`. When searching multiple keywords (e.g. `['python developer', 'data engineer']`), the first keyword yields up to 50 jobs on page 1, causing `len(jobs) >= limit` to trigger immediately and break out of the outer keyword loop. Subsequent keywords are completely skipped.
2. **Uncontrolled & Redundant Detail Page Requests:**  
   In `src/scrapers/blognone.py:188` (`_fetch_detail_description`) and `src/scrapers/jobthai.py:197` (`_fetch_job_description`), detail page requests are performed for every item encountered during search without checking if the job is already known in the state cache (`seen_jobs.json`) or database storage, and without pacing delays (`time.sleep(self.REQUEST_DELAY)`). This wastes HTTP bandwidth, slows pipeline runs, and risks IP rate-limiting.

## Changes

### 1. `src/scrapers/base.py`
- Update `BaseScraper.scrape` signature to accept optional `known_ids`:
  ```python
  @abstractmethod
  def scrape(
      self,
      keywords: Optional[List[str]] = None,
      limit: int = 50,
      known_ids: Optional[set[str]] = None,
  ) -> List[RawJob]:
  ```

### 2. `src/scrapers/jobsdb.py`
- In `scrape()`:
  - Track `keyword_count` per keyword loop iteration.
  - Change page-level and item-level break conditions to `if keyword_count >= limit: break`.
  - Remove the outer keyword break `if len(jobs) >= limit: break` so all target search keywords are processed up to `limit` items each.

### 3. `src/scrapers/blognone.py`
- In `_parse_job(item, known_ids=None)`:
  - If `job_id in (known_ids or set())`: skip `_fetch_detail_description` and use `fallback_desc`.
  - If `job_id` is new and `self.fetch_details` is True: call `time.sleep(self.REQUEST_DELAY)` before `_fetch_detail_description(url)`.
- In `scrape(keywords, limit, known_ids=None)`:
  - Change inner breaks to `if keyword_count >= limit: break`.
  - Remove outer keyword loop break so all keywords are searched.
  - Pass `known_ids` into `_parse_job`.

### 4. `src/scrapers/jobthai.py`
- In `_parse_job(item, known_ids=None)`:
  - If `job_id in (known_ids or set())`: skip `_fetch_job_description` and use empty/listing description.
  - If `job_id` is new and `self.fetch_details` is True: call `time.sleep(self.REQUEST_DELAY)` before `_fetch_job_description(numeric_id)`.
- In `scrape(keywords, limit, known_ids=None)`:
  - Change inner breaks to `if keyword_count >= limit: break`.
  - Remove outer keyword loop break so all keywords are searched.
  - Pass `known_ids` into `_parse_job`.

### 5. `main.py`
- Define per-adapter default limits:
  ```python
  DEFAULT_SCRAPER_LIMITS = {
      "JobsDBScraper": 150,
      "BlognoneScraper": 30,
      "JobThaiScraper": 30,
  }
  ```
- Update `run_scrapers(config, limit=None, state=None, storage=None)`:
  - Resolve `known_ids`: if `state` is provided, collect `set(state._seen.keys())`.
  - For each adapter, determine its limit: if `limit` is explicitly provided, use `limit`; otherwise use `DEFAULT_SCRAPER_LIMITS.get(name, 50)`.
  - Pass `known_ids` into `scraper.scrape(keywords=keywords, limit=adapter_limit, known_ids=known_ids)`.
- Update `run_full_pipeline` and `run_alert_pipeline`:
  - Pass `state` and `active_storage` into `run_scrapers`.

### 6. `docs/contexts/task-ledger.md`
- Update Task 0.4 item upon completion.
